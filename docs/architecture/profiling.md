# Profiling architecture

Profiling is an explicit tool path, not instrumentation on ordinary parsing or CLI commands. `nexus-profiling` provides bounded warm-up/sample configuration, `Instant` wall-time samples, min/median/mean/max, sample standard deviation, and an approximate 95% confidence interval for the mean. It keeps raw nanosecond samples and includes target OS/architecture, CPU environment string, compiler version, package version, debug/release mode, and an optional `NEXUS_OS_VERSION` field. Set that variable from PowerShell with `$env:NEXUS_OS_VERSION = [Environment]::OSVersion.VersionString` to make OS comparisons explicit.

`nexus profile <file>` separately times read-only snapshot creation and metadata parsing once. `nexus benchmark <file>` snapshots input once, warms up, and repeatedly calls the PE/ELF metadata parser in memory. It compares each parse result with the first parse to ensure repeated runs produce equal metadata. I/O is intentionally outside the parser benchmark timing. Reported throughput is an **equivalent container-size rate** (input container size divided by median parse time); the metadata parser validates boundaries and extracts headers but does not scan section payloads. It must not be interpreted as physical bytes scanned per second.

`nexus benchmark native-ffi` measures batches of 256 calls to the versioned native addition ABI. `nexus benchmark memory-allocation` measures batches of 256 4 KiB `Vec` allocation/free pairs. These verify and time existing interfaces; the allocation path does not collect allocator events or peak memory. Both produce the same versioned raw-sample schema with workload-specific operation counts and throughput.

The JSON report uses schema version 1 and includes workload, sample configuration, raw samples, summary statistics, throughput, environment data, supported coverage, and unavailable stages. `tools/python/compare_benchmarks.py` checks workload and environment identity, requires a configurable minimum sample count, and classifies a candidate only when both median threshold and approximate confidence intervals support it. Results are advisory by default.

Current metrics are wall time and derived container-size rate only. CPU call-stack sampling, per-function instrumentation, allocation counts, peak memory, I/O latency distributions, worker utilization, and Phases 03/04 stages are not implemented. No changes to parser hot paths are justified by a benchmark until repeated same-machine measurements identify a stable bottleneck.
